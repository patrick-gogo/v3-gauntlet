# Lap

Read `v3-gauntlet:ticket-workspace` first (project config, rulings, scripts). `TW` = `$SKILL_DIR/../ticket-workspace/scripts`. `Q` = `node "$TW/notion-queue.mjs"`. `CFG` = the project config `.claude/v3-gauntlet.md`.

**Where things run.** The laptop packs, starts, fetches and pushes. The devbox lead builds, reviews, tests and writes the handoff, following `docs/gauntlet/RULES.md`. The devbox has none of these plugins: everything the lead needs travels as files in the repo.

**Laptop rules.**
- Never send the user's working checkout to the devbox: a lap is packed and pushed from a **clean temporary worktree at the base**, so local uncommitted edits never leave the laptop.
- `docs/gauntlet/` is never committed in the user's checkout and never pushed to GitHub.
- The board never blocks a lap: a `could-not-run` from `notion-queue.mjs` is reported in one line and the lap goes on.

## Finding devbox
- `DG` = the newest `~/.claude/plugins/cache/devbox/devbox/*/scripts/devbox-git` (`ls -1 ... | sort -V | tail -1`). None → stop: the devbox plugin is not installed (`/plugin install devbox@devbox`, then `/devbox:setup`).
- Start, follow-up and result go through the devbox MCP tools (`start_agent`, `get_result`, `wait_for_agents`, `send_followup`); load them with ToolSearch if they are deferred.
- `REPO` = the main checkout's folder name (what `devbox-git push` prints as `repo=` from the main checkout). Always pass it explicitly: `bash "$DG" push "$REPO"`, `bash "$DG" fetch "$REPO"`.

## Lap record
`LR` = `~/.v3-gauntlet/laps/<repo>/<lap>/` (`TICKETS_HOME`'s parent overrides `~/.v3-gauntlet`). `lap.md` holds `key: value` lines written with `bash "$TW/state.sh" "$LR/lap.md" set <key> <value>`: `lap`, `job`, `job_branch`, `base`, `base_branch`, `tickets` (space-separated IDs), `status` (`running`, `returned`, `round2`, `pushed`), `started`, `returned`. `packed/` keeps a copy of what was sent; `handoff.md` the latest handoff.

## /v3-lap (start)
1. **Tickets.** Given IDs → those. Otherwise, with `queue: notion`, `$Q list --status Queued` (the order is the board's Order). For each: `WS=$(bash "$TW/ticket-ws.sh" path "<id>")`; its `phase` must be `approved` (Planned). Skip any other ticket with its reason (not planned on this laptop, still planning, already built). None left → say so and stop.
2. **Lap id:** `lap-$(date +%Y%m%d-%H%M)`. Stop time: `CFG` `lap_stop_time` (default `06:30`) in `lap_timezone` (default the space's `Asia/Manila`), as a date and time, never a bare time: `STOP=$(node "$SKILL_DIR/scripts/stop-time.mjs" <lap_stop_time> <lap_timezone>)` (exit 2: bad time or zone in `CFG`, say so and stop). Then check `STOP` looks like `YYYY-MM-DD HH:MM` (`printf '%s' "$STOP" | grep -Eq '^[0-9]{4}-[0-9]{2}-[0-9]{2} [0-9]{2}:[0-9]{2}$'`); anything else, an empty value included, means the script did not run as expected: say so and stop. Parallel: `CFG` `lap_parallel` (default `off`: one ticket at a time, as the house rule "one heavy thing at a time" suggests).
3. **Clean worktree.** `B=<CFG base_branch or the remote default>`; `git fetch origin "$B" -q`; `BASE=$(git rev-parse "origin/$B")`. `WT="<CFG lap_worktree_dir, else <parent of the main checkout's folder (see push day)>/<repo> worktrees>/gauntlet-<lap>"` (the folder name may hold a space, so always quote it); `git worktree add --detach "$WT" "$BASE"`.
4. **Pack:** `bash "$SKILL_DIR/scripts/lap-pack.sh" [--vault "<CFG prior_art_vault>"] "$WT" "<lap>" "<WS>"...`. With `prior_art_vault` set, each ticket also gets `prior-art/` (`prior-art.sh`: the vault's notes on the same files and feature, at most 3 extracts, never whole files) and the lap gets the vault's `learnings/`. Exit 2 → show the reasons, remove the worktree, stop; when the only reason is the vault folder, say so and pack again without `--vault` (prior art never blocks a lap).
5. **Rules:** write `"$WT/docs/gauntlet/RULES.md"` = `"$SKILL_DIR/templates/RULES.md"` followed by `CFG`'s `## Gates`, `## Stack` and `## House rules` sections copied verbatim (under those headings). No such section in `CFG` → write `## Gates` with the tickets' recorded `gate.<name>` commands and say the stack is not described. When `CFG` names a `reviewer_agent`, append `## Project conventions review` with that agent's instructions (its definition file without the frontmatter, from `.claude/agents/<name>.md` in the project or `~/.claude/agents/<name>.md`): the devbox has no agents, so the lead's conventions critic reads them from here.
6. **Brief:** write `"$WT/docs/gauntlet/<lap>/lead-brief.md"` from `"$SKILL_DIR/templates/lead-brief.md"`: `{lap}`, `{packed_at}` (`date -u +%Y-%m-%dT%H:%M:%SZ`), `{base}`, `{base_branch}`, `{stop_time}` (`$STOP`), `{timezone}`, `{parallel}`, `{git_name}` and `{git_email}` (the main checkout's `git config user.name` and `git config user.email`), and one `{ticket_rows}` line per ticket from `tickets.tsv` plus its state (`budget_impl_max`, `budget_review_max`): `| <n> | <id> | <title> | devbox/<lap>/<branch> | <depth> | <tasks> | <impl budget> | <review budget> |`.
7. **Send:** from `$WT`, `bash "$DG" push "$REPO"`; note `base=` (the snapshot ref). Then `start_agent` with `mode: lead`, `source: local`, `repo: $REPO`, `base: <that ref>`, `title: "Gauntlet lap <lap>"`, `task:` exactly
   `Run the gauntlet batch in docs/gauntlet/<lap>/lead-brief.md. Read docs/gauntlet/RULES.md first. The clean base is <BASE>; it must be the parent of your starting commit. Never push.`
8. **Record:** create `LR`, copy `"$WT/docs/gauntlet/"` to `"$LR/packed/"`, set `lap`, `job`, `job_branch` (from the start result), `base`, `base_branch`, `tickets`, `status running`, `started`. In each ticket's state: `set lap <lap>`. Board: `$Q status --key <id> --status Running --notes "lap <lap>, job <job>"`.
9. **Clean up:** `git worktree remove --force "$WT"` (everything in it was sent and copied to `packed/`).
10. **Announcement:** when `CFG` has a `## Lap announcement` section, fill its template with `{tickets}` (the IDs in order, joined with " and " for two, commas before that), `{ticket_lines}` (one line per ticket: `<id> <title>`, titles in English), `{ticket_urls}` (one URL per ticket when the section says how to build them), `{count}`, `{stop_time}` (`$STOP`) and `{lap}`, and deliver it as the section says (a draft, never a team post). A failure is one line; the lap is already running.
11. Tell the user in a few lines: the lap id, the job id, the tickets in order, the stop time, the prior art packed per ticket (extract count and learnings named, or "none found"), where the announcement draft went, and that they can close the laptop; `/v3-lap result` brings it home.

## /v3-lap result [lap]
Default lap: the newest record with `status running` or `round2`.
1. `get_result <job>`. Still running → say so (and how long), stop.
2. `bash "$DG" fetch "$REPO"`. The job's branch arrives as `refs/remotes/<job_branch>` (it already starts with `devbox/`), each ticket branch as `refs/remotes/devbox/<lap>/<branch>`.
3. Read the handoff from the job branch: `git show "refs/remotes/<job_branch>:docs/gauntlet/<lap>-handoff.md"` (round 2: `<lap>-handoff-r2.md`). Missing → the lead did not finish: show its summary, mark every ticket Needs you on the board, stop. Save it as `"$LR/handoff.md"`; `set status returned`, `set returned <time>`. Then put it on each ticket's card: for each ticket, `$Q page --key <id> --file "$LR/handoff.md" --child "Handoff <lap>"` (round 2: `--child "Handoff <lap> r2"`, so round 1's page stays). Any failure (exit 1 card missing, 2 bad input, 3 could-not-run) is one line and the step goes on.
3b. **Final review:** for each ticket, `git show "refs/remotes/<job_branch>:docs/gauntlet/<lap>/tickets/<id>/final-review.md" > "<WS>/final-review.md"` (RULES 2.8b). Missing → one line ("no final review for <id>"); push day will run a review instead. Then `$Q page --key <id> --file "<WS>/final-review.md" --child "Final review <lap>"`, and when `CFG` has a `## Review copy` section, also copy it where that section says (free text; `{id}` and `{date}` placeholders). Failures are one line each.
4. **Board:** for each ticket row in section 1: `Ready` → `$Q status --key <id> --status Ready --notes "lap <lap>: ready"`; anything else → `--status "Needs you" --notes "lap <lap>: <reason>"`.
5. Show the user section 0 as one block per question (`**<n>. <short title>** · <level>`, then `- **Question:**`, `- **Pick:**`, `- **Why:**` on their own lines, and a last line `To accept every pick: <the reply>`), rewriting it into that layout when the handoff did not use it, and section 1 (the ticket table), and the path to the full handoff. Answers go back with `/v3-lap answer`; ready tickets go out with `/v3-lap push`.
6. **Proposed learnings:** when the handoff's section 6 has blocks, show each one numbered (slug, claim, components) with the line `Keep them with /v3-lap learn "1 lock 2 skip"` (`edit: <text>` replaces the claim and body). Nothing is written to the vault here.

## /v3-lap learn [lap] "<reply>"
Only on the user's word, one answer per proposed learning in the handoff's section 6: `lock`, `skip`, or `edit: <text>`.
1. No `prior_art_vault` in `CFG` → show the locked blocks for the user to copy and stop.
2. For each `lock` or `edit`: the file is `<prior_art_vault>/learnings/<slug>.md`. It exists → never overwrite: show both and ask whether to merge into the existing note. Otherwise write the block (frontmatter plus body, with `date: <today>` added to the frontmatter; an `edit` replaces the claim and body first). The frontmatter needs `feature:` and `components:`; one missing → ask instead of writing.
3. `set learned "<slugs written>"` in `lap.md` and list the files written.

## /v3-lap answer [lap] "<reply>"
1. Count section 0's questions; parse with `bash "$TW/ruling-reply.sh" <n> "<reply>" --yesno <numbers of the yes/no questions, comma-separated>` (the last question, "Ready tickets go to push day?", is always yes/no, so `keep` there means yes; exit 2 → show it and ask again). Free-text answers to yes/no questions are forwarded verbatim.
2. Record the answers in each ticket's `rulings.md` as `source: user` rulings (T-level from the question). In `lap.md`: `set push_answer <yes|no|text>`, and `set changes "<space-separated ticket IDs with a change answer>"` (empty when none).
3. If any answer asks for a change: `send_followup <job>` with `Owner's answers to section 0 of docs/gauntlet/<lap>-handoff.md: <the parsed lines>. Run round 2 as RULES.md section 3 says. Never push.`; `set status round2`; board `Running` for the tickets that change. Otherwise nothing is sent.

## /v3-lap push [lap] [ids]
Only on the user's explicit word. Default: every ticket the handoff marks Ready, when `lap.md`'s `push_answer` is yes. Never by default: a ticket listed in `lap.md`'s `changes`, or any ticket while the lap's `status` is `round2` (its branch is about to change); those go only when the user names their IDs.
`<git_email>` and `<git_name>` = the main checkout's `git config user.email` and `user.name`. The main checkout's folder is `dirname "$(git rev-parse --path-format=absolute --git-common-dir)"`, which is right even when the session sits inside a worktree. For each ticket, first set `TMP="<CFG lap_worktree_dir, else <parent of the main checkout's folder>/<repo> worktrees>/push-<id>"` (always quote it: the folder may hold a space). Every git step that needs a checkout runs in `TMP`, never in the main checkout.
1. `R=refs/remotes/devbox/<lap>/<branch>`. `bash "$SKILL_DIR/scripts/lap-check.sh" "$R" "<base>" --author <git_email>` (it also refuses tool attribution in any commit message). Not ok → show why, skip this ticket. One exception: when every failure line is an `author` or `committer` line (the devbox committed as its own default user), the commits may be re-authored in step 3 (the re-author resets both).
2. **Drift:** `git fetch origin "<base_branch>" -q`; `bash "$SKILL_DIR/scripts/drift.sh" "$R" "origin/<base_branch>"`. Exit 1 (conflict) → name the conflicting files, skip this ticket (the owner merges by hand). Otherwise show `behind` and `overlap` in one line; files changed on both sides are worth a look in step 5.
3. Local branch: `git branch "<branch>" "$R"`. If `<branch>` already exists locally and differs, it may be this push day's own re-authored copy from an earlier run that failed later: treat it as the same branch (skip creating it and skip the re-author) when its tree equals `$R`'s (`git rev-parse "<branch>^{tree}"` = `git rev-parse "$R^{tree}"`), it has as many commits on `<base>` as `$R`, and every commit's author and committer email is `<git_email>`. Any other difference: stop for this ticket and ask (never overwrite a local branch). `git worktree add "$TMP" "<branch>"`. **Re-author (only for the author-only exception in step 1):** first prove the commits are unpublished: `git ls-remote --exit-code origin "refs/heads/<branch>"` must exit 2 (no such remote branch); otherwise skip the ticket and ask. Then `GIT_EDITOR=true GIT_SEQUENCE_EDITOR=true git -C "$TMP" -c user.name="<git_name>" -c user.email="<git_email>" rebase -q --exec 'git commit --amend --no-edit --reset-author --no-verify --no-gpg-sign' <base>`. A failed rebase: `git -C "$TMP" rebase --abort`, remove `TMP`, `git branch -D "<branch>"` (it was created in this step), skip the ticket. Run `lap-check.sh` again on the local `<branch>` with `--author <git_email>`; any failure skips the ticket the same way.
4. Secrets: `git diff "<base>..<branch>" | bash "$TW/secret-scan.sh" [--deny-file .claude/v3-gauntlet-deny.txt] -`. Any hit → show rule and location (never the value), skip this ticket.
5. **Review:** `bash "$SKILL_DIR/scripts/review-head.sh" "<WS>/final-review.md" "<branch>"`. `ok` → reviewed. `same-tree <sha>` (re-authored, identical code) → add `rereviewed_head: <sha>` to the frontmatter of `<WS>/final-review.md` and of the `## Review copy` destination. `stale`, or exit 2 (no final review) → run the review command `CFG`'s `## Review copy` section names (else `v3-gauntlet:v3-review`) on `TMP` before going on, and weigh step 2's overlap files there.
6. **Merge the base (optional):** when `CFG` says `push_merge_base: yes` and step 2 reported `behind` > 0: `git -C "$TMP" merge --no-edit "origin/<base_branch>"` (never rebase). A conflict here: `git -C "$TMP" merge --abort`, skip the ticket.
7. In the ticket's state: `set push_approved yes` (the guard hook blocks the push without it), `set branch <branch>`.
8. **Push** from `TMP`, never from the main checkout. `push_skip_hooks` defaults to `yes` for a lap (the gates already ran on the devbox): `git -C "$TMP" push --no-verify -u origin "<branch>"`, and the PR body gets one line: "Pushed with --no-verify: the project's gates ran in the lap (see evidence above)." Only when `CFG` says `push_skip_hooks: no`: `git -C "$TMP" push -u origin "<branch>"`, so the hooks run in `TMP`; `TMP` has no installed dependencies, so a hook that needs them fails there: report it and skip the ticket, never retry in the main checkout. A failed push: `set push_approved no`.
9. Open the PR as `CFG`'s `## Push day` section says. Without that section: `gh pr create --draft --base <base_branch> --title "<type>(<id>): <title>" --body-file "<WS>/pr-body.md"`, the body built from the ticket's bar, the handoff's evidence and rulings for that ticket. Either way, write the body to `<WS>/pr-body.md` first and scan it before the PR is created: `bash "$TW/secret-scan.sh" [--deny-file .claude/v3-gauntlet-deny.txt] "<WS>/pr-body.md"` (the body is built from devbox-written text). Any hit → show rule and location, fix the body or stop for this ticket. Name commits by subject in the body, not by sha (a re-author changes the shas). No tool attribution of any kind.
10. **Review request:** when the handoff's section 5 has a block for this ticket and `CFG` has a `## Review request` section, fill that section's template with the block's fields plus `{pr_url}` and `{ticket_url}`, and deliver it as the section says (a draft, never a team post). Without the section, show the fields in the reply.
11. `set pr_url <url>`, `bash "$TW/state.sh" "<WS>/state.md" phase pr`; board `--status "PR open" --report <url>`. Remove the push worktree: `git worktree remove "$TMP"`; when it refuses, look at `git -C "$TMP" status --porcelain` first and use `--force` only when nothing listed is tracked work.
Then `set status pushed` on the lap if every ticket is done or skipped, and list the PR URLs. After a merge, `/v3-ticket <id>` closes the ticket as usual.
